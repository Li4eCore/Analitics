# ETL-процессы в Power Query

Конспект по модулю курса [Microsoft Power BI, Power Query, DAX](https://stepik.org/course/190679/syllabus).

---

## Подключение к источникам данных

**PostgreSQL (например, БД Nordwind):**
`Get Data → More → Database → PostgreSQL Database → Connect` → указать
Host / Port / Database / User / Password.

Можно либо написать свой SQL-запрос (Advanced options → SQL statement),
либо загрузить таблицы целиком галочками и нажать `Transform Data`.

**Частая ошибка при подключении к PostgreSQL:** ошибка шифрования соединения —
решается через `File → Options and settings → Data source settings →
Edit Permissions → снять галочку "Encrypt connections"`.

**Другие источники:**

| Источник | Путь | Особенность |
|---|---|---|
| CSV/TXT | `Get Data → File → Text/CSV` | проверять File Origin (кодировку), Delimiter |
| Excel | `Get Data → File → Excel Workbook` | можно выбрать несколько листов сразу |
| XML | `Get Data → File → XML` | Power Query сам разбирает структуру |
| JSON | `Get Data → File → JSON` | автопарсинг иерархии |
| Google Sheets | `Get Data → Other → Google Sheets` | вставить ссылку, авторизация через Google |
| Папка с файлами | `Get Data → File → Folder` | для объединения однотипных файлов (см. ниже) |

**Если данные из CSV/TXT отображаются в одном столбце** — почти всегда
неверно выбран `Delimiter`, нужно поменять вручную.

## Подключение папки и объединение файлов (Append Queries)

Когда данные разбиты на много файлов одинаковой структуры (например,
отчёты за каждый месяц) — Power Query может подключить всю папку разом
и объединить файлы в одну таблицу автоматически.

**Шаги:** `Get Data → File → Folder` → выбрать папку → `Combine →
Combine & Transform Data` → выбрать файл-образец → Power Query создаёт
запрос, который сам подхватывает новые файлы при добавлении в папку.

**Append Queries** — вертикальное объединение (добавление строк одной
таблицы в конец другой). Обязательное условие — **идентичная структура
столбцов** у обеих таблиц.
`Home → Combine → Append Queries as New → Two tables`.

Частый сценарий: часть данных лежит в БД (например, за 1996-1998),
часть — в CSV-файлах за более старые периоды (1990-1995). Перед
объединением из CSV-таблицы убирают лишние столбцы, чтобы структура
совпала с таблицей из БД, и только потом объединяют через Append.

## Типы данных

| Тип | Когда использовать |
|---|---|
| Whole Number | целые числа: ID, счётчики, количество |
| Decimal Number | научные расчёты |
| Fixed Decimal Number | деньги, цены |
| Percentage | процентные значения |
| Date / Time / Date-Time | даты, время, метки времени |
| Text | имена, адреса, описания |
| True/False | флаги, индикаторы |

**Смена типа для нескольких столбцов сразу:** выделить (Ctrl/Shift +
клик) → правой кнопкой → Change Type.

**Зачем хранить ID как текст, а не число:** сохраняет ведущие нули
(001 не превращается в 1), защищает от поломки модели, если появятся
буквенно-цифровые ID (A15), и убирает риск случайной агрегации ID
как числа в визуализациях.

## Работа с текстом

**Регистр и очистка:** UPPERCASE / lowercase / Capitalize Each Word,
`Trim` (убрать пробелы по краям), `Clean` (убрать непечатаемые символы),
`Add Prefix` / `Add Suffix`.

**Split Column** — разделение столбца на несколько, способы:
By Delimiter, By Number of Characters, By Positions, а также по
переходу регистра/цифра↔буква (реже используются).

**Extract (извлечение части текста):** Length, First/Last Characters,
Range, Text Before/After/Between Delimiters.

**Replace Values** — замена значений (опечатки, стандартизация,
замена кодов). **Replace Errors** — замена ошибочных значений (деление
на ноль, неверное приведение типа) на 0/пустую строку/NULL.

**Fill Down / Fill Up** — заполнение пустых ячеек значением сверху/снизу.

## Pivot / Unpivot

- **Pivot** — превращает "длинный" формат в "широкий": уникальные
  значения одного столбца становятся новыми столбцами (удобно для
  чтения человеком, отчётов).
- **Unpivot** — обратная операция, "широкий" → "длинный": несколько
  столбцов сворачиваются в пары "Атрибут-Значение". **Большинство
  визуализаций Power BI требуют именно "длинный" формат.**

## Календарь (Calendar table)

Отдельная таблица дат — стандартная практика для корректной работы
временных фильтров и группировок, даже если в исходных данных уже
есть все даты.

**В DAX — три варианта:**

```dax
CALENDARAUTO()   -- весь диапазон дат по всей модели (может захватить лишнее,
                  -- например, дату рождения сотрудника из другой таблицы)

CALENDAR(MIN(orders_total[order_date]), MAX(orders_total[order_date]))
                  -- явные границы по конкретному столбцу

CALENDAR(MINX(orders_total, [order_date]), MAXX(orders_total, [order_date]))
                  -- то же самое через функции итерации MINX/MAXX
```

**В Power Query (язык M):**
```
= List.Dates(min_date, Number.From(max_date) - Number.From(min_date), #duration(1,0,0,0))
```
`List.Dates(start, count, step)` — список дат от `start`, `count` штук,
с шагом `step`. Разница дат в числах даёт нужное количество дней.
Результат преобразуется в таблицу: `Transform → To Table`.

**Power Query vs DAX для календаря:**

| | Power Query | DAX |
|---|---|---|
| Производительность | быстрее (статичная таблица, считается один раз) | пересчитывается при каждом взаимодействии |
| Гибкость | легко добавлять кастомные колонки на языке M | реагирует на фильтры динамически |
| Обновление диапазона | нужно менять вручную | подстраивается автоматически |

Для больших моделей обычно предпочтительнее Power Query — если только
не нужна динамическая реакция на фильтры.

**Стандартные столбцы календаря:** Year, Month Name, Start of Month,
Quarter, Week of Year, Day of Week Name — все через `Add Column → Date`.

## Возраст и длительность (Duration)

```
Add Column → Date → Age  →  получаем Duration
Transform → Duration → Total Years  →  переводим в годы (дробное число)
Transform → Rounding → Round Down  →  целое число полных лет
```

## Локализация и региональные настройки

Если данные русскоязычные, а Power BI настроен на другую локаль (или
наоборот) — числа и даты могут распознаться неверно (например, `32,38`
в русской локали — дробное число, в английской — текст/ошибка).

**Смена локали файла:** `File → Options and settings → Options →
Current File → Regional Settings → Locale for import`.

**Важно:** смена глобальной локали **не переконвертирует** уже
импортированные данные автоматически — нужно вручную удалить шаг
`Changed Type` в Power Query и заново применить тип через
`Transform → Data Type → Using Locale...`, явно указав, в какой локали
записаны исходные данные.

## Index Column и Conditional Column

**Index Column** — добавляет последовательный номер строки. Полезно
для восстановления исходного порядка после сортировки/фильтрации,
создания искусственного ключа, если в данных нет уникального
идентификатора.

**Conditional Column** — аналог `CASE WHEN` из SQL, только через UI:
```
If unit_price >= 50 → 'Luxury'
Else If unit_price >= 25 → 'Premium'
Else If unit_price >= 15 → 'Standard'
Else → 'Economy'
```
Значение для сравнения можно взять не только вручную, но и из другого
столбца той же строки, или из **параметра** (см. ниже).

---

## Параметры (Parameters)

Именованная переменная, значение которой можно менять в одном месте —
и оно автоматически обновится во всех запросах, где используется.

`Home → Manage Parameters → New Parameter` → задать Name, Type,
Current Value. Удобно для порогов классификации (как в Conditional
Column выше) — вместо трёх зашитых чисел (50/25/15) используются три
параметра, которые можно поменять без правки формул.

---

## Custom Column (расчётный столбец)

```
Add Column → Custom Column
New column name: revenue_discount
Формула: [unit_price] * [quantity] * (1 - [discount])
```
Синтаксис обращения к столбцу — в квадратных скобках `[имя_столбца]`.

## Merge Queries (объединение по ключу — аналог JOIN)

`Home → Merge Queries` (изменяет текущий запрос) или
`Merge Queries as New` (создаёт отдельный новый запрос, не трогая
исходные). Выбираются два запроса и ключевые поля для соединения
(аналог `ON` в SQL).

**Join Kind — соответствие типам JOIN в SQL:**

| Power Query | SQL-аналог |
|---|---|
| Inner | INNER JOIN |
| Left Outer | LEFT JOIN |
| Right Outer | RIGHT JOIN |
| Full Outer | FULL OUTER JOIN |
| Left Anti | LEFT JOIN ... WHERE ... IS NULL |
| Right Anti | RIGHT JOIN ... WHERE ... IS NULL |

**Fuzzy Matching** — нечёткое сравнение текста при объединении (порог
схожести 0-1, игнорирование регистра) — нужно для текстовых полей с
возможными опечатками (адреса, названия компаний). Для точных числовых
ключей (`order_id`) не нужен.

---

## Group By (агрегация — аналог GROUP BY)

`Transform → Group By`, два режима:
- **Basic** — группировка по одному столбцу, одна агрегация
- **Advanced** — несколько столбцов группировки (`Add grouping`) +
  несколько агрегаций одновременно (`Add aggregation`)

**Доступные операции:** Sum, Average, Median, Min, Max, Count Rows,
Count Distinct Rows, All Rows.

---

## Настройки обновления запроса

Правый клик по запросу в панели Queries:

- **Enable load** — загружать ли результат запроса в модель Power BI.
  Снимают для промежуточных/служебных запросов, чьи данные уже вошли
  в финальную объединённую таблицу.
- **Include in report refresh** — обновлять ли запрос при общем
  Refresh отчёта. Снимают для редко меняющихся справочников и закрытых
  исторических данных — тогда обновление только вручную.

Снятие этих галочек не про удаление данных, а про производительность:
меньше промежуточных таблиц в модели, быстрее общее обновление отчёта.

## Data Category (категории данных)

Метаинформация, которая не меняет сами данные, а подсказывает Power BI,
как их использовать — в первую очередь для карт: `Country`, `City`,
`State or Province`, `Latitude`/`Longitude`, а также `Web URL` (делает
значения кликабельными ссылками) и `Image URL` (отображение картинок).

**Если визуал карты не работает:** проверить `File → Options and
settings → Options → Security → Map and Filled Map visuals` — должна
быть включена галочка использования этих визуалов, плюс перезапуск
Power BI Desktop.
